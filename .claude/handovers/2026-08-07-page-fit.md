## Decisions + why

- **Demotions travel beside the content, not inside `entry.detail`.** That field is the user's
  (markdown export honours only it, `entryDetail` reads it first), so the fit passes a `demoted` id
  set and `pagesFor` takes `(content, demoted)`. The measuring render and the export render then
  take identical inputs — parity by construction, which is the whole point of a preflight.
- **`cutIds` is separate from `droppedIds`** rather than one merged list: same badge, different
  tooltip, and `fitNotices` reports only the page-fit drops (a cap-cut notice would fire on nearly
  every export, and the invisible-ink layer already lists them as `cut_for_space`). There is a test
  pinning that silence so it doesn't get "fixed" later.
- **Pins beat the cap, not the page.** A pinned entry is kept by `capContent` regardless of rank;
  the page fit may still drop it (last, per `dropOrder`) — but then it is *reported*, which is what
  was wrong before.
- **The sidebar grammar is a nested array inside `cv.sidebar`**, not a second spec field, so one
  list still reads top-to-bottom the way the page does.
- **The section-toggles guide was activated for Lukas to type, and then typed by me** after
  "implement this". If he'd rather have typed it, the guide and its tests are unchanged and the
  source is one `git checkout` away.
- **Not done on purpose:** raising the skills cap. Measured 6 skills ≈ 1 line ≈ 8.2pt, and every
  skill is already in the invisible-ink layer for ATS — 18 is an editorial number, not a spatial one.
