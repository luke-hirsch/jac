# Roadmap — 2026-05-28

Snapshot of where the project stands and the next five phases, in order.

## Current state

- Career DB models in [backend/jac/models.py](backend/jac/models.py): `Domain`, `Location`, `CvEntry` (abstract), `Education`, `Certification`, `Skill`, `Job`, `Project`, `Language`. Every entry is user-scoped; `Skill.years_of_experience` derives from `first_used` and the earliest `Job.started` / `Project.started` it touches.
- CV pipeline in [backend/jac/cv.py](backend/jac/cv.py) — `CV` class with `deterministic_filter`, `extract_keywords`, `ai_filter_entries`, `ai_rank_entries`, `agentic_tailor`. Scored entries get transient `.relevance_score` / `.relevance_reason`.
- LLM prompt wrappers in [backend/jac/llm.py](backend/jac/llm.py): `extract_job_keywords`, `analyze_job`, `score_entries_for_job`, `score_entries_with_analysis`. All go through `llm_connector.complete` and parse JSON via `_parse_json`.
- Markdown rendering in [backend/jac/render.py](backend/jac/render.py) — `CvRender` class with `export_md()`. PDF/DOCX will happen on the frontend from structured API payloads.
- Admin: all career models registered in [backend/jac/admin.py](backend/jac/admin.py).
- Smoke-test CLI: [backend/jac/management/commands/cv_test.py](backend/jac/management/commands/cv_test.py).
- Tests: 50 in [backend/jac/tests.py](backend/jac/tests.py), all passing.
- LLM aliases in [backend/lukehirsch/settings.py](backend/lukehirsch/settings.py): `default` (Anthropic Sonnet 4.6), `fast` (Ollama qwen), `reasoning` (OpenAI o4-mini).

**Not yet built:** DRF, API endpoints (`jac/views.py` is empty, `jac/urls.py` doesn't exist, project [urls.py](backend/lukehirsch/urls.py) only routes `admin/`), Application/FollowUp models, frontend (still default Vite template), `spa` app (empty scaffold), async stack, deployment.

---

## Phase 1 — DRF serializers + CRUD APIs

- Install DRF, add `rest_framework` to `INSTALLED_APPS`, add a `REST_FRAMEWORK` settings block (session + token auth, paginated defaults).
- New `backend/jac/serializers.py` — one serializer per career model: `Domain`, `Location`, `Education`, `Certification`, `Skill`, `Job`, `Project`, `Language`. Nested reads where it helps (e.g. `Skill.domains`, `Job.skills`), PK writes.
- New `backend/jac/views.py` — `ModelViewSet` per model, filtered to `request.user`'s entries (override `get_queryset` and `perform_create` to inject the user). Permission class: `IsAuthenticated`.
- New `backend/jac/urls.py` — DRF `DefaultRouter` registrations.
- Wire into project [urls.py](backend/lukehirsch/urls.py) under `/api/jac/`.
- Tests: list/create/retrieve/update/delete per model, plus user-scoping (one user cannot see another's entries).

## Phase 2 — Frontend CRUD

- Add `react-router-dom`, an HTTP client (axios or fetch wrapper), and TanStack Query for cache/mutation handling.
- Auth surface: login form against Django's session/token endpoint.
- One list + edit page per career model, mirroring the admin: table view, create modal, edit drawer, delete confirm.
- Keep styling minimal — this is plumbing, not the portfolio UI.

## Phase 3 — Async stack

- Add Daphne (ASGI) so we can do streaming responses and websockets later.
- Add Celery + Redis for background jobs. First job: scheduled follow-up reminders (needs an `Application` / `FollowUp` model — design it as part of this phase).
- Wire a `celery.py` into [backend/lukehirsch/](backend/lukehirsch/), beat schedule for periodic checks.
- LLM streaming endpoints exposed over ASGI (the synchronous DRF endpoints stay for CRUD).

## Phase 4 — Comment & docstring cleanup

- Remove every existing comment in `backend/` and `frontend/` that explains *what* the code does.
- Replace with module/class/function docstrings that explain *why* and document the public contract (args, returns, raises).
- Inline comments only where a non-obvious constraint, invariant, or workaround needs to be flagged.
- Same pass on the frontend — JSDoc on exported functions/components.

## Phase 5 — Deployment

- `Dockerfile` for backend (Python 3.12, Daphne entrypoint) and frontend (multi-stage: Vite build → nginx serve).
- `docker-compose.yml`: backend, frontend, postgres, redis, celery worker, celery beat, nginx reverse proxy. The existing [config/](config/) nginx config is the starting point.
- `.env.example` checked in, real `.env` mounted via compose.
- GitHub Actions:
  - `ci.yml` — lint + `python manage.py test` + `npm run build` on every PR.
  - `deploy.yml` — on push to `main`, build images, push to registry, SSH into the VPS, `docker compose pull && up -d`.
- DB migration strategy: SQLite → Postgres before first deploy.

## Verification per phase

- **Phase 1:** `python manage.py test jac` passes; `curl -u user:pw http://localhost:8000/api/jac/jobs/` returns only that user's jobs.
- **Phase 2:** Manual click-through — log in, create one of each model, edit one, delete one, log out, log in as a second user, verify isolation.
- **Phase 3:** Fire a Celery task from the shell, see it execute in the worker log; Daphne serves the same endpoints as `runserver`.
- **Phase 4:** `git diff` shows comments removed and docstrings added; tests still pass.
- **Phase 5:** `docker compose up` brings the full stack up locally; a push to a test branch runs CI green; a push to main deploys cleanly to the VPS.
