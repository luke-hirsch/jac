# Roadmap — 2026-06-12 (output-first revision)

Supersedes the now-archived [roadmap-2026-06-02.md](archive/roadmap-2026-06-02.md)
(and the older `06-01` / `05-29` / `05-28` roadmaps under [archive/](archive/)).

The project is **lukehirsch**: a monorepo for a personalized portfolio site **plus**
the Job Application Creator (JAC) — a tool that ingests a job posting and produces a
**complete German application: a tailored CV + a cover letter** (*Anschreiben*) drawn
from the user's career database.

## Why this revision

The `06-02` roadmap was "frontend-first": build the CRUD UI, then iterate backend gaps.
That worked — the career editors, auth, and the CV-tailoring pipeline all shipped, and a
full personal CV can now be authored through the UI. We then drifted off the written plan
a couple of times (3a-bis, 3d-bis were unplanned polish slices). The code is in good shape;
the *plan* is what needs resetting.

The new organizing insight: **the value of JAC is the finished application document, and
we have never produced one.** The pipeline *selects* CV entries well, but:

- there is **no cover letter** — the `ResumeSnippet` model exists and is CRUD-exposed but
  nothing in the pipeline consumes it;
- the output is **English-only and structural** — `CvRender` dumps fields, with no German
  rendering, while nearly every target posting is German;
- the selection quality has **never been dogfooded against a real, capable LLM** — only the
  free Ollama default and mocked tests.

So this revision is **output-first**: get the tool to emit a real, German, CV-plus-letter
package, dogfood it, *then* build the frontend that drives it, *then* deploy. Each backend
phase produces a tangible artifact you can read; each frontend phase makes that artifact
editable; deployment comes once the local loop is real.

## Frontend stack (locked 2026-06-02, unchanged)

TanStack Router + Query (no Start framework — server is Django), Tailwind v4 + shadcn/ui,
TanStack Form (editors) + Table (lists), Vite same-origin proxy for cookies/CSRF in dev.

  + TOTP + WebAuthn passkeys + recovery codes; `_allauth/` mounted; admin MFA gate.

- **spa UserProfile** at `/api/spa/profile/` + account-delete at `/api/spa/account/`.
- **CV pipeline** ([backend/jac/cv.py](../../backend/jac/cv.py)) — deterministic + LLM
  filtering/ranking; 5-rung `ai_tailor_with_fallback` (conversational → filter → keyword →
  deterministic → unfiltered); multi-language stopwords; markdown render via `CvRender`.
- **Career-data model** — full relations: `Skill.related_skills` (symmetric) + `builds_on`
  (directed) + `years_of_experience_override`; `ResumeSnippet` (intro/achievement/value/closing)
  + `Education/Certification/Project/Job` cross-links. JSON `cv_export` / `cv_import` round-trip.
- **Frontend** — Phase 2a–2c + 3c/3d/3d-bis: auth + account pages, the full `/cv/*` CRUD UI

  domain filter, skill-bubble cloud).

**Not yet built — the gaps this roadmap closes:** no cover letter; no German output; no
real-LLM dogfooding of selection quality; no PDF; no deployment.

## Phases — in order

### Phase 4 — Backend: CV validation + cover-letter generation (German output)

Make the tool emit a complete, German, dogfooded application package — entirely backend,
runnable from management commands.

**4a — LLM config + CV-pipeline validation gate.** *(First setup guide:
[phase-4a-setup-guide.md](phase-4a-setup-guide.md).)*
- Add a real paid `LLMConfig` to user 1 via Django admin (the existing `LLMConfigAdmin`
  with `PasswordInput` — no UI needed yet; the `/settings/llm` page is Phase 5a).
- Extend the existing `cv_test` into a `cv_eval` command: batch over a postings corpus
  (`data/postings/*.txt`, real German + English), run `ai_tailor_with_fallback` per posting
  (and optionally per alias), and log per posting **which tier won, timing, per-section entry
  counts, and the rendered CV markdown**; optional LLM-judge critique.
- Run it, record findings in `phase-4a-findings.md`, make the **go/no-go** call for 4b.
- Selection quality is language-agnostic (the scoring prompts match on meaning, not tokens),
  so 4a runs against German *postings* with English *output* — German output arrives in 4d.

**4b — CV pipeline refinement.** Multi-pass / agentic improvements to
[cv.py](../../backend/jac/cv.py), driven strictly by 4a findings — only build what the
findings justify. Candidate levers: iterate `analyze_job` → `score_with_analysis` over more
than one pass; **consume the `builds_on` / `related_skills` edges** the model now carries (a
posting that hits a skill should pull its prerequisites/cluster); tune `_MIN_PER_SECTION` and
the threshold; tighten the conversational selection contract.

**4c — Cover-letter generator.** The headline feature.
- Seed a handful of real `ResumeSnippet` rows via Django admin (intro / achievement /
  value_statement / closing), tagged with `domains` / `skills` for relevance matching.
- Build a `CoverLetter` builder class in **new `backend/jac/letter.py`** (parallel to `CV`):
  consumes a tailored `CV` snapshot + the relevance-matched `ResumeSnippet`s + the posting (and
  its `analyze_job` output), and emits a cover letter. **Same AI-escalation/fallback discipline
  as `CV`**: top tier asks the LLM only for connective tissue between hand-written snippets
  (voice stays the user's, not "AI slop"); lower tiers degrade to snippets-verbatim → a minimal
  template. Add a `jac.llm.generate_cover_letter(...)` wrapper (threads `user=`, uses
  `UserProfile` for sign-off).
- Render via a `LetterRender` (parallel to [render.py](../../backend/jac/render.py)); a
  management command produces the **full package** (CV markdown + letter markdown) for a posting.
  *Naming note:* this `CoverLetter` is a generator class, distinct from the deferred `CoverLetter`
  *tracking model* in the outview.
- DRF endpoint wiring is optional here (the frontend in 5b can drive a `/api/jac/.../generate/`
  action); the management-command path is the acceptance gate.

**4d — German output localization.** Selection already matches cross-language; only *rendering*
needs a target-language variant — the filtering pipeline is untouched.
- **Deterministic labels (Django i18n, no LLM):** `LocaleMiddleware` + `LOCALE_PATHS` + `de`;
  wrap `CvRender` section headings + the `gettext_lazy` enums (proficiency/category/fluency/
  job-type) in `gettext`; `makemessages -l de` → fill `locale/de/LC_MESSAGES/django.po` →
  `compilemessages`.
- **Free-text prose (LLM, stored + editable — not regenerated per run):** add
  `translations = JSONField(default=dict)` to the abstract `CvEntry` base (one migration across
  all six entry tables) → `{"de": {"description": "...", "title": "..."}}`, plus a `tr(field, lang)`
  resolver; `ResumeSnippet` gets the same. A glossary-protected `jac.llm.translate_entries(entries,
  target_lang, llm, user=)` wrapper translates `description` / job `title` / `field_of_study` /
  snippet prose, passing proper nouns + tech terms (skill names, companies, institutions, URLs)
  through verbatim. Target language detected from the posting (add `language` to `analyze_job`'s
  schema) with a per-run override, threaded as `target_language` through `ai_tailor_with_fallback`.
  After selection, lazily fill only the chosen entries' missing `translations[lang]`, then persist.
- The **cover letter** is generated directly in the target language (a prompt param), so 4d gives
  it German body text without a translate round-trip.

### Phase 5 — Frontend: tailoring UI + document editor + PDF export

Make the Phase-4 package drivable and editable from the browser.

**5a — LLM-config UI.** `/settings/llm` — CRUD over `LLMConfig` (write-only `api_key`, provider
dropdown, model autocomplete, `has_api_key` badge) + `/settings/llm/usage` — read-only
`LLMRequestLog` with date filter + aggregate spend. (Backend already exists at `/api/llm/`.)

**5b — Tailoring editor.** Paste a posting → see the detected language + analysis → the tailored
CV selection (per-entry keep/drop override) → the generated cover letter (editable prose) → all
in the target language, with hand-fixable `translations`.

**5c — Layout editor + PDF export.** A **template-driven** layout with strong railguards — the
user parameterizes a fixed, typographically-sound template (fonts, accent, section order,
margins) rather than free-form design — and exports the CV + letter package to PDF. Backend PDF
renderer (WeasyPrint or ReportLab) extends [render.py](../../backend/jac/render.py) /
`LetterRender`.

### Phase 6 — Revision: end-to-end hardening of Phases 4–5

Not new features — make the whole **paste-posting → German CV + letter → PDF** loop reliable.
Expand automated coverage (the cover-letter + translation + render paths; first frontend
Playwright smoke), fix the bugs dogfooding surfaces, tighten the rough edges. Exit criterion:
the user can produce a send-ready German application for a real posting without touching the
backend by hand.

### Phase 7 — DevOps + first deployment

**7a — Security hardening:** DRF throttles (scoped + anon), secure-cookie + `SECURE_*` / HSTS /
CSP headers gated on `DEBUG`, secrets audit, N+1 audit on M2M-heavy list endpoints, serializer
validation bounds, multipart/avatar upload validation, wider `did_recently_authenticate` reauth.

**7b — Containerization:** Dockerfiles (backend: Python + Daphne; frontend: Vite build → nginx) +
`docker-compose.yml` (backend, frontend, postgres, redis, celery worker/beat, nginx using existing
[config/](../../config/)); `.env.example` checked in; SQLite → Postgres migration.

**7c — CI/CD + first deploy:** GitHub Actions — `ci.yml` (lint + `python manage.py test` +
`npm run build`) and `deploy.yml` (build → push → SSH `docker compose pull && up -d`) targeting
the **IONOS** server; first production deployment; Sentry (env-gated) + DB backup cron.

## Verification per phase

- **4a:** `python manage.py llm_check --user 1` answers against the real provider; `cv_eval`
  writes one CV markdown + one findings row per posting; `phase-4a-findings.md` records the
  go/no-go.
- **4b:** A posting that hits a skill with prerequisites pulls the `builds_on` closure into the
  selection; findings-targeted regressions covered by tests.
- **4c:** The full-package command emits a CV **and** a cover letter for a posting; the letter
  visibly stitches the seeded `ResumeSnippet`s (not generic AI prose); LLM failure degrades to
  snippets-verbatim, not a crash.
- **4d:** Tailoring a German posting renders section headings + enum labels in German and the
  selected entries' prose via stored `translations["de"]` (tech terms + company names untranslated);
  a second run for the same language issues no new translate call; the cover letter body is German.
- **5:** Paste a posting in the browser → edit the selection + letter → export a PDF of the package.
- **6:** A fresh real German posting → send-ready PDF, no backend hand-holding; suite green incl.
  the cover-letter/translation/render paths + a frontend smoke.
- **7:** `docker compose up` brings the full stack up locally; push to `main` deploys to IONOS;
  Sentry captures a thrown error.

## Cross-cutting principles to preserve

Invariants the working code already holds; keep them as new phases land:

- **Per-user LLM config end-to-end.** Every LLM call in user-driven flows passes `user=` so personal
  `LLMConfig` rows are honoured; `settings.LLM["default"]` is the free fallback only. The new
  `generate_cover_letter` + `translate_entries` wrappers must thread `user=`.
- **All career entries are user-scoped.** Inherited from the abstract `CvEntry`. `translations` lives
  on that base; the `CoverLetter` generator reads only the request user's snippets.
- **API keys never leave the server.** `LLMConfig.api_key` Fernet-encrypted; `PasswordInput` in admin;
  never echoed in any serializer.
- **Every model in admin.** Any new model (`translations` is a field, not a model; none expected in
  Phase 4 beyond that) gets a `ModelAdmin`.
- **Secrets via `os.getenv()`.** Never hardcoded.
- **Django ORM only.** No raw SQL.
- **Snippets keep the human voice.** Cover-letter generation stitches hand-written `ResumeSnippet`s
  with minimal LLM glue — the LLM writes connective tissue, not the substance.
