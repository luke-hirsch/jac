# [fullstack] portfolio block links

**Branch:** `fullstack/block-links` (stacked on `frontend/portfolio-creator-ux` — it reuses that
guide's `ContentPicker`. Guide 1's implementation currently rides in the working tree uncommitted;
these two land as a dependency pair. Seal Guide 1 on its own branch first if you want clean,
separately-mergeable history.)

**Roadmap:** portfolio phase follow-up. Guide 2 of two — the data-model half of "blocks link to all
kinds of stuff" (the design decision from the pro/con: **Reference — a JSON `type:pk` id-list on the
block**, reusing the `content.featured` grammar, not an FK on the career DB).

## Context / goal

`PortfolioBlock` (spa) is owner-authored content tagged with a `domains` M2M. Blocks range from broad
("welcome") through domain-level ("I've been a full-stack engineer…") to job/project-specific ("in
this project I learned about friendship"). We want a block to **optionally reference an ordered mix of
other content** — career entries, other blocks, even placeholder blocks — and render those references
**nested beneath it** on the public page.

Decision (locked): the link lives on the **block**, as a JSON **ordered `type:pk` id-list**
(`["project:3", "job:12", "block:5"]`) — the exact grammar `content.featured` already uses. This
reuses:

- the server resolver `spa.portfolio.resolve_items()` (already turns `["job:12","block:7"]` → item
  dicts),
- the id-grammar validator `spa.serializers.FEATURED_ID_RE` (already in the file),
- the client picker `ContentPicker` (guide 1) and the pure algebra in `link-form.ts`.

No new career-DB columns, no cross-app FK, one migration in the app that owns blocks.

**Rendering rule (locked default):** a block resolves its `links` **one level deep** — nested blocks
are leaves (no further expansion), and a block never nests itself. Career entries nested under a
rendered block are **not repeated loose** in the auto-generated `more` section (blocks always keep
their own slot). The explicitly-curated `featured` list is left exactly as the owner ordered it.

### 2. `backend/spa/serializers.py` — validate the id-list

Reuse the existing `FEATURED_ID_RE` (top of the file, line ~30). Add a cap constant beside it:

```python
MAX_BLOCK_LINKS = 50  # a block references a handful of items; this only guards abuse
```

In `PortfolioBlockSerializer`, declare `links` explicitly (a `ListField`, so it survives the
multipart image path as repeated fields — a bare model JSONField would demand a JSON _string_ there),
add it to `fields`, and validate:

```python
class PortfolioBlockSerializer(serializers.ModelSerializer):
    """..."""

    user = serializers.HiddenField(default=serializers.CurrentUserDefault())
    # Explicit ListField (not the model-JSONField automap) so repeated multipart `links`
    # fields parse on the image path, matching how `domains` already survives multipart.
    links = serializers.ListField(
        child=serializers.CharField(), required=False
    )

    class Meta:
        model = PortfolioBlock
        fields = (
            "id",
            "user",
            "kind",
            "title",
            "body",
            "image",
            "alt_text",
            "domains",
            "links",
            "favourite",
            "order",
            "is_active",
            "updated_at",
        )
        read_only_fields = ("id", "updated_at")

    # get_fields / validate unchanged …

    def validate_links(self, value):
        """Grammar-only (like `content.featured`): '<type>:<pk>' ids, order-preserving
        dedupe, capped. Existence is NOT checked — dead ids drop at resolve time."""
        seen, out = set(), []
        for i in value:
            if not FEATURED_ID_RE.match(i):
                raise serializers.ValidationError(
                    "links must be a list of '<type>:<pk>' ids."
                )
            if i not in seen:
                seen.add(i)
                out.append(i)
        return out[:MAX_BLOCK_LINKS]
```

> Leave `get_fields` and `validate` (the kind↔payload rule) exactly as they are.

### 3. `backend/spa/portfolio.py` — resolve + nest + claimed-exclusion

**3a. `_block_item`** — add a `nest` flag and resolve `links` one level deep, excluding self:

```python
def _block_item(block: PortfolioBlock, *, nest: bool = True) -> dict:
    item = {
        "id": f"block:{block.pk}",
        "type": "block",
        "kind": block.kind,
        "title": block.title,
        "body": block.body,
        # MEDIA_URL-relative; dev Vite proxies /media, prod nginx must serve it.
        "image_url": block.image.url if block.image else None,
        "alt_text": block.alt_text,
        "domains": sorted(d.name for d in block.domains.all()),
        "links": [],
    }
    if nest and block.links:
        # One level only: nested items are built as leaves (nest=False), and a block
        # never nests itself — so no recursion / cycles.
        ids = [i for i in block.links if i != item["id"]]
        item["links"] = resolve_items(block.user, ids, nest=False)
    return item
```

**3b. `resolve_items`** — thread `nest` through to nested blocks (leaves don't re-expand):

```python
def resolve_items(owner, ids: list[str], *, nest: bool = True) -> list[dict]:
    """Join featured ids against the live DB, preserving order. Dead / foreign /
    malformed ids drop silently (the cv-doc philosophy: selection frozen, text live).
    `nest` False builds block items as leaves (no `links` expansion) — used when
    resolving a block's own links, to bound nesting to one level."""
    wanted: dict[str, list[int]] = {}
    for i in ids:
        t, _, pk = i.partition(":")
        if pk.isdigit():
            wanted.setdefault(t, []).append(int(pk))
    found: dict[str, dict] = {}
    models_map = _career_models()
    for t, pks in wanted.items():
        if t == "block":
            rows = PortfolioBlock.objects.filter(
                user=owner, is_active=True, pk__in=pks
            ).prefetch_related("domains")
            found.update({f"block:{b.pk}": _block_item(b, nest=nest) for b in rows})
        elif t in models_map:
            qs = models_map[t].objects.filter(user=owner, pk__in=pks)
            if t != "language":
                qs = qs.prefetch_related("domains")
            found.update({f"{t}:{o.pk}": _career_item(t, o) for o in qs})
    return [found[i] for i in ids if i in found]
```

(only the signature line and the `_block_item(b, nest=nest)` call changed.)

**3c. claimed-exclusion helper** — add near the payload assembly section (after `resolve_items`):

```python
def _claimed_ids(items: list[dict]) -> set[str]:
    """Ids nested under any block in `items` (one level)."""
    out: set[str] = set()
    for it in items:
        if it.get("type") == "block":
            out.update(sub["id"] for sub in it.get("links", []))
    return out


def _drop_claimed(featured: list[dict], more: list[dict]) -> list[dict]:
    """Career items nested under a rendered block don't also float loose in `more`;
    blocks always keep their own slot. `featured` (owner-curated) is left untouched."""
    claimed = _claimed_ids(featured) | _claimed_ids(more)
    return [i for i in more if i["type"] == "block" or i["id"] not in claimed]
```

```ts
function blockMultipart(input: BlockInput, image: File): FormData {
  const fd = new FormData();
  fd.set("kind", input.kind);
  fd.set("title", input.title);
  fd.set("body", input.body);
  fd.set("alt_text", input.alt_text);
  fd.set("favourite", String(input.favourite));
  fd.set("order", String(input.order));
  fd.set("is_active", String(input.is_active));
  for (const d of input.domains) fd.append("domains", String(d));
  for (const l of input.links) fd.append("links", l);
  fd.set("image", image);
  return fd;
}
```
