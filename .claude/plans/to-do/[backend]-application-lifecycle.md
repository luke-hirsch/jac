# [backend] Application lifecycle — foundation

## Context / goal

Roadmap: the **application lifecycle tracking** work (the "now" flow Lukas sketched — create →
deadline → approve → send → follow-up → response). This is the **first of four** guide-sized
chunks; the other three sit on infrastructure that doesn't exist yet and each get their own guide:

| # | chunk | why later |
|---|-------|-----------|
| 1 | **this guide** — status state-machine + deadline + tracking fields | self-contained backend |
| 2 | outbound email-send from the site | needs a server-side PDF source (export is frontend-only today) |
| 3 | scheduled follow-up / reminder digest | needs **Celery Beat** (new dev process) — also the substrate for the future 6 a.m. "X applications ready" digest |
| 4 | richer response handling | builds on this chunk's `response` state |

**This guide delivers the foundation and nothing else:**

- an **`approved`** status inserted into a real, **guarded** state-machine (`draft → approved → sent
  → follow_up / response`, plus `inactive`), with legal moves enforced server-side;
- a per-application **`deadline`**, auto-filled from the posting during a generation run (extending
  the `AddressExtract` call that already runs there — **no new LLM call**) and manually overridable;
- **tracking fields** the later chunks need: `delivery_method` (email/manual), `sent_by_system` (the
  flag chunk 3's auto-follow-up keys on), `response_outcome` + `notes`, and
  `approved_at` / `sent_at` / `responded_at` timestamps;
- a dedicated **transition endpoint** so `status` stops being freely PATCH-able.

**Design decisions (confirmed with Lukas):**

- **Deadline capture** = *inside the generation run + manual override.* `AddressExtract` gains a
  `deadline` field; `generate_run` writes it to `application.deadline` **only while it's still
  unset** — same fill-if-empty discipline as `cv_content`/`cover_letter`, so a hand-typed deadline
  is never clobbered.
- **Statuses** = *extend + guarded transitions.* One `apply_transition()` method on the model owns
  the legal-move map and stamps the side-effect fields; the view is a thin wrapper. `status` and the
  stamped fields become **read-only** in the serializer — moves go through `POST …/transition/`.
- **Response** = *outcome + note, stops the clock.* Moving to `response` carries an optional
  `response_outcome` (interview/offer/rejected/other) and `note`, stamps `responded_at`. "Stops the
  clock" is structural: chunk 3's digest query will only look at `status in (sent, follow_up)`, so a
  `response` application is naturally skipped — no extra field needed here.

**Explicitly NOT in this guide:** any outbound email, any Celery Beat / scheduled task, any PDF
work. `sent_by_system` is added as a forward hook but has **no writer** in this chunk (it stays
`False`; chunk 2's mailer will flip it).

Add the transition map + methods (after `clean`, still inside `JobApplication`):

```python
    # Legal status moves. `inactive` is reachable from any active state (posting pulled, or the
    # user shelves it) and reactivates to `draft`. Recording a `response` is terminal-ish — the
    # follow-up "clock" (chunk 3) only looks at `sent`/`follow_up`, so `response` stops it.
    TRANSITIONS: dict[str, set[str]] = {
        StatusChoices.draft: {StatusChoices.approved, StatusChoices.inactive},
        StatusChoices.approved: {
            StatusChoices.draft,
            StatusChoices.sent,
            StatusChoices.inactive,
        },
        StatusChoices.sent: {
            StatusChoices.follow_up_sent,
            StatusChoices.response,
            StatusChoices.inactive,
        },
        StatusChoices.follow_up_sent: {
            StatusChoices.response,
            StatusChoices.inactive,
        },
        StatusChoices.response: {StatusChoices.inactive},
        StatusChoices.inactive: {StatusChoices.draft},
    }

    def can_transition(self, to: str) -> bool:
        return to in self.TRANSITIONS.get(self.status, set())

    def apply_transition(
        self,
        to: str,
        *,
        delivery_method: str = "",
        response_outcome: str = "",
        note: str = "",
    ) -> None:
        """Validate + perform a status move, stamping the relevant side-effect fields.

        Raises `TransitionError` for an unknown target, an illegal move, or an unknown
        delivery-method / outcome value. Does **not** save — the caller persists, so a rejected
        move leaves both the instance and the DB row untouched.
        """
        if to not in self.StatusChoices.values:
            raise TransitionError(f"Unknown status {to!r}.")
        if not self.can_transition(to):
            raise TransitionError(
                f"Cannot move an application from {self.status!r} to {to!r}."
            )
        now = timezone.now()
        if to == self.StatusChoices.approved:
            self.approved_at = now
        elif to == self.StatusChoices.sent:
            if delivery_method:
                if delivery_method not in self.DeliveryMethod.values:
                    raise TransitionError(
                        f"Unknown delivery method {delivery_method!r}."
                    )
                self.delivery_method = delivery_method
            self.sent_at = now
        elif to == self.StatusChoices.response:
            if response_outcome:
                if response_outcome not in self.ResponseOutcome.values:
                    raise TransitionError(
                        f"Unknown response outcome {response_outcome!r}."
                    )
                self.response_outcome = response_outcome
            if note:
                self.notes = note
            self.responded_at = now
        self.status = to
```

> `TRANSITIONS` keyed by `TextChoices` members works as plain-string keys — `TextChoices` values are
> `str` subclasses, so `self.TRANSITIONS.get(self.status)` (a plain `str`) hits them by hash/equality.

Leave the existing `clean()` (posting-inactive → `inactive`) as is — it's an orthogonal guard for
admin/forms and doesn't route through `apply_transition`.

```python
    @extend_schema(
        request=inline_serializer(
            "ApplicationTransition",
            {
                "to": serializers.ChoiceField(JobApplication.StatusChoices.values),
                "delivery_method": serializers.CharField(
                    required=False, allow_blank=True
                ),
                "response_outcome": serializers.CharField(
                    required=False, allow_blank=True
                ),
                "note": serializers.CharField(required=False, allow_blank=True),
            },
        ),
        responses=JobApplicationSerializer,
    )
    @action(detail=True, methods=["post"])
    def transition(self, request, pk=None):
        """Advance the application through its lifecycle. Legal moves live in
        `JobApplication.TRANSITIONS`; an unknown or illegal target is a 400. The model stamps
        the side-effect fields (approved_at / sent_at / responded_at, delivery_method,
        response_outcome, note) — `status` itself is read-only over plain PATCH."""
        application = self.get_object()
        try:
            application.apply_transition(
                request.data.get("to"),
                delivery_method=(request.data.get("delivery_method") or "").strip(),
                response_outcome=(request.data.get("response_outcome") or "").strip(),
                note=(request.data.get("note") or "").strip(),
            )
        except TransitionError as exc:
            return Response({"to": [str(exc)]}, status=status.HTTP_400_BAD_REQUEST)
        application.save()
        return Response(
            JobApplicationSerializer(application, context={"request": request}).data
        )
```

> `request.data.get("to")` being `None` (or absent) falls into `apply_transition`'s "unknown status"
> branch → `TransitionError` → 400, so no separate presence check is needed.

```tsx
                placeholder="Note (optional)…"
                value={note}
                onChange={(e) => setNote(e.target.value)}
              />
              <Button
                size="sm"
                disabled={busy}
                onClick={() =>
                  move({ to: "response", response_outcome: outcome, note })
                }
              >
                Record response
              </Button>
            </div>
          </div>
        )}

        {app.status === "response" && (
          <p className="text-sm text-muted-foreground">
            Response recorded
            {app.response_outcome
              ? `: ${OUTCOME_LABELS[app.response_outcome]}`
              : ""}
            {app.notes ? ` — ${app.notes}` : ""}
          </p>
        )}

        {app.status === "inactive" && (
          <Button
            size="sm"
            variant="outline"
            disabled={busy}
            onClick={() => move({ to: "draft" })}
          >
            Reopen
          </Button>
        )}
      </CardContent>
    </Card>
  );
}
```
